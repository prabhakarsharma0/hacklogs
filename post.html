Bypassing WAF to achieve Blind XSS on a Fintech App

P

Prabhakar

Security Researcher

TL;DR: Found a Blind XSS on a fintech platform. Cloudflare WAF blocked standard payloads, so I used Unicode encoding to bypass it and execute the payload in the admin dashboard.

1. Reconnaissance

While testing the application, I noticed a feedback form that accepted JSON data. The endpoint was api/v1/feedback. This was interesting because WAF rules are usually strict on standard form data, but often fail to inspect deeply nested JSON payloads.

2. Exploitation (The WAF Bypass)

When I tried a basic payload like <script>alert(1)</script>, I got a 403 Forbidden. I knew there was a WAF. I started using URL encoding and HTML entities, but they were also blocked. Finally, I tried Unicode encoding.

<img src=x onerror=alert(document.domain)>

By encoding the payload as %u003Cimg..., the WAF failed to detect it, but the backend server decoded it correctly, leading to execution in the admin panel.

3. Impact

Since this was a Blind XSS, the payload executed when an admin viewed the feedback dashboard. This could have allowed an attacker to steal admin session cookies, perform actions on behalf of the admin, or even pivot to internal systems.

4. Remediation (How to Fix)

  • Contextual Output Encoding: Ensure that all user input is encoded based on where it's being rendered (HTML, Attribute, JavaScript).
  • Content Security Policy (CSP): Implement a strict CSP header to block inline scripts and unauthorized external sources.
  • WAF Tuning: Update WAF rules to decode and inspect Unicode-encoded payloads before letting them pass.
